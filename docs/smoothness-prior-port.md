# The algebraic smoothness prior, ported from Julia

**Goal.** Compute ACEpotentials.jl's `algebraic_smoothness_prior` in pure numpy
(`ace_jax/construct/prior.py`), so a fit can proceed when an exported `.npz`
lacks `gamma` — and so future authoring paths can emit it themselves. Refitting
or evaluating an existing exported model stays 100% Julia-free.

## What Julia computes

`ACEpotentials.jl src/models/smoothness_priors.jl` (v0.10.2):

```
algebraic_smoothness_prior(model; p = 4, wl = 2/3, wn = 1.0) =
      smoothness_prior(model, bb -> sum((b.l/wl)^p + (b.n/wn)^p for b in bb))
```

The functional is evaluated on the FULL per-column nnll basis: for each
species, the tensor B-functions' `(n, l)` bodies followed by the pair
singletons `(n, 0)`, `n = 1..n_pair` — i.e. `(n_tensor + n_pair) * NZ` columns
laid out `[tensor x NZ | pair x NZ]`, exactly the species-blocked order of
`fit/rows.py:_place` (`ACEModel.site_descriptors`). The result is `Diagonal(gamma)`.

Two Julia branches are deliberately NOT ported and must be asserted away:

- the embedded-model n-folding triggers only on `meta["embedding"]`, which
  `ace1_model` never sets;
- the `_coupling_scalings` product is commented out in the Julia source; only
  the unused ACE1-compat variant applies it.

The constants (`p, wl, wn`) are the PRIOR's defaults, fixed by the exporter's
argument-free call (`export_model.jl:352`) and independent of the
basis-selection level parameters (`wL`/NZ): basis selection only decides which
nnll exist.

## The port (`construct/prior.py`)

- `unflatten_nnll(nnll_flat, nnll_len)` — the oracle fixtures' flat layout to
  per-column `[(n, l), ...]` lists.
- `smoothness_prior(nnll; p, wl, wn)` — the formula, sequential float64
  accumulation in Julia's generator order.
- `model_nnll(meta)` / `gamma_from_model(meta)` — rebuilds the full basis from
  an export's `meta["nnll"]` (the exporter's own `get_nnll_spec(m.tensor)`
  dump, `n_B` entries shared across species) tiled per species, plus the pair
  singletons. Rebuilding the tensor spec from `aspec_r`/`aa_specs` instead is
  NOT possible from the npz alone: it would need the Rnl table's per-l block
  layout, which the export does not carry.

Bit-exactness: with `wl = 2/3` every term is `(3l)^4/16` or `n^4` — an integer
over `2^4`, exactly representable in float64 — and partial sums stay far below
`2^53`, so Julia's and Python's float paths agree bit-for-bit. The parity test
asserts equality, not a tolerance: a tolerance would hide a convention drift.

## Verification pyramid

1. **Formula** — `tests/test_smoothness_parity.py` feeds the port the oracle's
   own inputs: four committed fixtures
   (`fixtures/smoothness_ref_*.npz`, orders 2-4, 2-3 species, incl. the
   degenerate-block `wL = 0.5` shape) generated by
   `julia/smoothness_reference.jl`, storing `gamma` together with the FULL
   per-column nnll basis. Compared bit-for-bit, plus layout/constancy tests.
2. **End-to-end** — `fixtures/si_fitted.npz` stores the gamma
   `algebraic_smoothness_prior` returned on the real model;
   `gamma_from_model` must reproduce it bit-for-bit from `meta["nnll"]` alone.
   The other ship exports (analytic radial, big basis, the NZ=2 `sige_nofit`
   refit target) are covered structurally (length, positivity, species
   replication, pair values `n^4`).

## Wire-in

`cli.py` (and `bench/acegp_cantor/run.py`) read `z["gamma"]` when present —
exported gamma stays authoritative — and otherwise rebuild via
`gamma_from_model(meta)` with a log line. Nothing else in the eval/fit path
changed.

CI: the `prior-parity` workflow (`.github/workflows/prior-parity.yml`)
regenerates the four oracle fixtures with Julia 1.11 and re-runs the parity
tests on every push touching the port, its tests, or the oracle script, and
weekly. Fixtures are committed, so pip-only environments never need Julia.
